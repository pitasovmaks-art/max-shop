# Точка Монтажа — статус проекта

Мини-приложение для Max Messenger. Магазин строительных инструментов с каталогом, корзиной и оформлением заказа.

---

## Стек

- **Frontend**: Vanilla JS, HTML/CSS (без фреймворков)
- **Backend**: Node.js + Express
- **БД**: PostgreSQL — Brainy Aquila, хост `192.168.0.5` (Timeweb внутренняя сеть), SSL `rejectUnauthorized: false`
- **S3**: Timeweb, бакет `tochka-montazha-images`, endpoint `s3.twcstorage.ru`
- **Деплой**: Timeweb App Platform
- **Продакшен URL**: `https://pitasovmaks-art-max-shop-c149.twc1.net`
- **Платформа**: Max Messenger Mini App SDK (`https://st.max.ru/js/max-web-app.js`)

## Архитектура выбора города

Пользователь выбирает город из полного списка 200+ городов РФ с поиском. Выбор хранится в:
- `localStorage('city')` — код `krd` или `msk`, TTL **15 минут**
- `localStorage('cityName')` — отображаемое название города
- `localStorage('cityTimestamp')` — время выбора

**Сопоставление:**
- 23 города **Краснодарского края** (Краснодар, Сочи, Новороссийск, Армавир, Анапа, Геленджик, Туапсе, Тихорецк, Кропоткин, Темрюк, Лабинск, Славянск-на-Кубани, Белореченск, Ейск, Тимашевск, Апшеронск, Горячий Ключ, Абинск, Гулькевичи, Курганинск, Новокубанск, Каневская, Усть-Лабинск) → код `krd`
- Все остальные города → код `msk`

Кнопка города в хедере показывает `cityName`. Клик → снова открывает экран выбора со списком и поиском.

## Структура цен

### Таблица `products`

Поля `price`, `price_krd`, `price_msk`, `price_delivery` — устаревшие, сохранены как фоллбек.

### Таблица `product_variants`

| Поле | Описание |
|---|---|
| `price`, `price_krd`, `price_msk`, `price_delivery` | Устаревшие, фоллбек |
| `price_krd_pickup` | Цена для Краснодарского края (самовывоз / по городу) |
| `price_msk_pickup` | Цена для остальных городов (самовывоз / по городу) |
| `price_msk_delivery` | Цена доставки по России (СДЭК) |
| `is_krd` | 1 = вариант для КРД, 0 = для остальных |

**Правило:** каждый вариант принадлежит одному региону (`is_krd`). В каталоге и карточке показываются только варианты нужного города с ненулевой ценой.

### Функция getEffectivePrice(variant, city, deliveryType)

- `city === 'krd'` → `variant.priceKrdPickup`
- `deliveryType === 'russia'` → `variant.priceMskDelivery`
- иначе → `variant.priceMskPickup`

Фоллбек: если новые поля = 0, используются старые поля (`priceKrd`, `priceMsk`, `price`).

### Форма вариантов в админке — два блока

- **«Краснодар и КК»** (зелёная рамка, `is_krd=1`) — Название + Цена самовывоз
- **«Все остальные города»** (синяя рамка, `is_krd=0`) — Название + Самовывоз + Доставка по России

## Способы получения заказа

| Способ | Код | Цена | Что показывается |
|---|---|---|---|
| 🏪 Самовывоз | `pickup` | pickup-цена для города | Список магазинов (фильтр по городу) |
| 🚗 По городу | `city` | pickup-цена для города | Поле адреса доставки |
| 📦 По России | `russia` | `price_msk_delivery` | Поиск отделений СДЭК (авто по городу) |

При переходе с pickup/city → russia показывается **модальное окно** с изменением цен (glassmorphism). При подтверждении применяются цены `price_msk_delivery`.

## tg_id — как передаётся

1. **Бот** при `/start` формирует кнопку: `web_app: SHOP_URL + '?tg_id=' + chatId`
2. **index.html** при загрузке читает `tg_id` из URL, сохраняет в `sessionStorage('tg_id')`
3. **cart.html** — аналогично, кнопка «Оформить заказ» передаёт `checkout.html?tg_id=...`
4. **checkout.html** — читает из URL или `sessionStorage`, передаёт в тело POST `/api/orders` как поле `tgId`
5. **orders.html** — читает из URL или `sessionStorage`, загружает заказы через `GET /api/orders/my?tg_id=...`

**Цепочка сохранения:** `URL ?tg_id= → sessionStorage('tg_id')` — работает пока открыта вкладка браузера.

## Бот Max Messenger (`bot.js`)

- **Режим: webhook** (POST `/webhook` в `server/index.js`)
- `API_BASE = 'platform-api.max.ru'`
- Регистрация: `registerWebhook()` при старте сервера
- Администраторы: `bot_admins.json` (каждый кто нажал /start)

**Команды:**
- `/start` / `bot_started` — приветствие + кнопка «🛒 Открыть магазин» (с `?tg_id=chatId`)
- `/myid` — отвечает своим chat_id
- `/reply ID текст` — только для админов

**Функции:**
- `notifyStore(order)` — уведомление менеджеру о новом заказе
- `notifyCustomer(tgId, orderId, status, extra)`:
  - `status='tracking'` → сообщение с трек-номером и ссылкой СДЭК
  - `status='in_progress/shipped/completed/cancelled'` → соответствующий текст
  - `extra` заполнен без явного `status='tracking'` → тоже отправляет трек-сообщение (обратная совместимость)

## Фронтенд — страницы

### `index.html` — Каталог
- Экран выбора города: 200+ городов РФ, поиск, алфавитный список
- Кнопка города в хедере (смена города)

### `src/catalog/product.html` — Карточка товара
- Свайп-галерея с миниатюрами (thumbnail strip с градиентным фоном)
- Варианты (только нужного региона, с ненулевой ценой)
- Нижняя панель: цена `#F85800` + кнопка «В корзину» (градиентный фон)
- Описание — крупный текст без рамки
- Тост при добавлении в корзину

### `cart.html` — Корзина
- Список позиций, изменение количества, удаление
- Кнопка «Оформить заказ» передаёт `tg_id` в URL checkout-а
- 4-кнопочный навбар

### `checkout.html` — Оформление заказа
- Три вкладки: Самовывоз / По городу / По России
- Самовывоз: список магазинов, фильтр по городу, бейдж открыто/закрыто
- По России: авто-загрузка отделений СДЭК для города пользователя, поиск по отделениям, выбор = адрес доставки
- Модальное окно смены цены при переключении на «По России»
- `tg_id` читается из URL или `sessionStorage`, передаётся в заказ

### `src/orders/orders.html` — Мои заказы (клиент)
- Загружает заказы через `GET /api/orders/my?tg_id=...`
- Цветные бейджи статусов: серый/синий/оранжевый/зелёный/красный
- Если есть `trackingNumber` → кнопка «Отследить посылку» (ссылка на СДЭК)
- Если `tg_id` не найден → пустой список
- 4-кнопочный навбар, обновляет ссылки с `tg_id`

### `admin/index.html` — Админ-панель
- Авторизация: пароль `1608`, JWT, сессия 60 минут
- Вкладки: Товары / Категории / Заказы / Магазины
- **Товары:** CRUD, фото в S3, варианты в двух блоках (КРД и МСК/РФ), без полей цен на уровне товара
- **Заказы:** фильтры по магазину/статусу/способу доставки; карточки с адресом доставки; поле трек-номера для не-самовывозных заказов с кнопкой «Отправить клиенту»
- **Статусы:** new / in_progress / shipped / completed / cancelled

## Нерешённые задачи / известные проблемы

### Критические
- **Debug-логи в продакшене** — в `orders.js`, `checkout.js`, `bot.js` добавлено логирование (`console.log`). Перед финальным релизом убрать.
- **tg_id из sessionStorage** — работает только в рамках одной вкладки браузера. Если пользователь открывает новую вкладку без `?tg_id=` — заказы не загрузятся. Решение: дополнительно сохранять в `localStorage` с TTL.
- **Старые заказы без tg_id** — у заказов, оформлённых до добавления поля `tg_id`, уведомления при смене статуса не отправятся (tg_id = NULL).
- **Блок трек-номера** — отображается для всех типов доставки кроме pickup/city. Если в старых заказах поле `delivery` пустое или дефолтное `'pickup'`, блок не покажется. Проверить реальные данные в БД.

### Функциональные
- **Уведомление при /start** — кнопка «Открыть магазин» в ответе на /start содержит `?tg_id=chatId`. При повторном открытии магазина (без /start) tg_id не передаётся, если ссылка закладкой — нужно проверить.
- **Checkout без ?tg_id в URL** — кнопка в cart.html передаёт `?tg_id=`, но если пользователь перешёл в корзину без `?tg_id`, sessionStorage тоже будет пуст.
- **Трек в admin** — после сохранения трек-номера вызывается `renderOrders()` → перезагрузка всего списка. На большом количестве заказов это медленно.

### Архитектурные
- Старые поля цен (`price`, `price_krd`, `price_msk`, `price_delivery`) в `products` и `product_variants` не удалены — занимают место, но работают как фоллбек.
- Поле `price` в `product_variants` всегда сохраняется как 0 (форма вариантов его не показывает).
- **Два отдельных бота** (КРД и МСК) — не реализовано.
- **Интеграция МойСклад** — не реализовано.
