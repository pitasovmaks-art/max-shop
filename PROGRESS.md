## Таблицы БД

### `orders`
| Поле | Описание |
|---|---|
| `delivery` | `pickup` / `city` / `russia` |
| `address` | Адрес (city) или пункт СДЭК (russia) |

### `user_map` — маппинг userId → chatId (основной бот)
Заполняется при каждом входящем сообщении. Используется в `notifyCustomer` как fallback.

### `support_admins` — маппинг userId → chatId для бота поддержки
Заполняется когда менеджер пишет боту поддержки. Хранится в БД (переживает деплои).

### `support_known` — известные клиенты бота поддержки
chat_id клиентов которые уже обращались в поддержку.

### `favorites` — избранное
```sql

    id         SERIAL PRIMARY KEY,
    tg_id      BIGINT NOT NULL,
    product_id BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(tg_id, product_id)
);
```

## tg_id — как передаётся и хранится

### Из бота в приложение
- При `bot_started` → `chat_id` берётся из `update.chat_id`
- При любом сообщении → `userId` и `chatId` сохраняются в `user_map`

### В браузере (`src/utils/tgid.js`)
Функция `getTgId()` ищет по приоритету:
1. `?tg_id=` в URL
2. `?startapp=tg_id_...` в URL
3. `sessionStorage('tg_id')`
4. `localStorage('tg_id')` с TTL 24 часа

### В заказе
`checkout.js` читает `getTgId()` и передаёт как `tgId` в тело `POST /api/orders`.

## Боты Max Messenger

### Основной бот (`bot.js`) — `id635009278943_bot`
- **Режим: webhook** → `POST /webhook`
- `bot_started` → приветствие с кнопкой магазина, `addAdmin(chatId)`
- `message_created` → сохраняет `userId→chatId` в `user_map`, пересылает всем администраторам
- `/start`, `/myid`, `/reply` — команды
- `notifyStore(order)` — уведомление менеджеру при новом заказе
- `notifyCustomer(tgId, orderId, status, extra)` — уведомление клиенту (с fallback через user_map)
- `request()` бросает ошибку при HTTP 4xx/5xx

### Бот поддержки (`bot-support.js`) — `id635009278943_1_bot`
- **Режим: webhook** → `POST /webhook-support`
- Запускается через `startSupportBot()` внутри той же `.then()` цепочки что и основной бот, обёрнут в `try/catch`
- Менеджеры определяются по `user_id` (одинаков у обоих ботов): `SUPPORT_ADMIN_USER_IDS = [5149723, 100067838]`
- `bot_started` от менеджера → сохраняет `userId→chatId` в таблицу `support_admins` в БД
- `bot_started` от клиента → приветствие «Опишите вопрос»
- Сообщение от клиента → «✅ Спасибо за обращение» + пересылка всем менеджерам из `support_admins`
- Ответ менеджера:
  - **Свайп-reply** на пересланное сообщение (через `msg.link.type === 'reply'`, извлекает ID из текста `🆔 ID: ...`)
  - **Команда `/reply <chat_id> <текст>`** — запасной способ
- `sendMessage` использует `POST /messages?chat_id=X` с `{ text, format: 'markdown' }` в body (как основной бот)

## Backend API

| Маршрут | Доступ | Описание |
|---|---|---|
| `POST /api/orders` | публичный | создание заказа |
| `GET /api/orders/my?tg_id=` | публичный | заказы клиента |

| `DELETE /api/favorites` | публичный | убрать из избранного `{ tgId, productId }` |
| `POST /api/support/admin-map` | публичный | сохранить userId→chatId менеджера поддержки |

## Известные проблемы / технический долг

- **tg_id в старых заказах** — заказы #1–23 без tg_id, уведомления не дойдут, не чинится
- **user_map vs chat_id** — маппинг строится только если пользователь писал боту. Если не писал — fallback не сработает
- **Старые поля цен** (`price`, `price_krd`, `price_msk`, `price_delivery` на уровне товара и варианта) — не удалены, используются как фолбэк
- **bot_admins.json** — все кто нажал `/start` считаются получателями пересылки. Нужно разделить на менеджеров и подписчиков
- **SIGTERM в логах при деплое** — нормальное завершение старого процесса, не проблема
- **Фото в корзине** — сохраняется только при добавлении через каталог; товары добавленные до этого коммита фото не имеют
